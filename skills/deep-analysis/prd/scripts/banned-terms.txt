# Banned terms — domain-leakage guard for DOC-006 (scripts/check-docs.py)
#
# The framework must stay stack- and domain-agnostic. Every example in
# agents/, rules/, templates/, skills/, project-context.md and README.md is
# meant to be generic; vocabulary borrowed from a consuming project (its
# product names, endpoint paths, enum values, repo names) turns a "generic"
# example into a leak that the next adopter has to reverse-engineer.
#
# Format
#   one term per line, matched case-insensitively
#   `#` starts a comment (whole-line or trailing)
#   `term :: path[, path]` exempts specific repo-relative files for that term
#
# Matching
#   Terms made only of word characters get a leading word boundary and allow
#   trailing word characters: `idt` will not match inside `width`, while
#   `remittance` still catches `remittances`. Terms containing punctuation or
#   spaces (`money-transfer`, `/transfer/`, `bank deposit`) match literally.
#
# Scope
#   Scanned: agents/ rules/ templates/ skills/ project-context.md README.md
#   Not scanned: scripts/tests/fixtures/ — those fixtures deliberately contain
#   bad examples so prd-lint.py has something to fire on. Use the `::`
#   allowlist for a legitimate use inside the scanned surface instead of
#   widening the scope.
